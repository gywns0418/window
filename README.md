# SnipShortcut

Windows 기본 **캡처 도구**를 사용자 지정 단축키(기본 `Ctrl + Alt + S`)로 실행하거나, 이미 열려 있으면 그 창을 앞으로 가져오는 트레이 상주 유틸리티입니다.

- 회사 보안 정책으로 `Win + Shift + S`가 막혀 있어도, **사용자가 직접 캡처 도구를 실행하는 것과 같은 경로**로 캡처 도구 앱을 열어 줍니다.
- 캡처, 클립보드 복사, 붙여넣기는 **Windows 캡처 도구가 그대로 처리**합니다. 이 프로그램은 클립보드를 읽거나 쓰지 않고, 이미지를 저장하거나 전송하지도 않습니다.

---

## 보안 정책 준수 원칙

| 항목 | 동작 |
| --- | --- |
| 실행 경로 | 캡처 도구 **앱 자체**만 실행합니다(`shell:AppsFolder\Microsoft.ScreenSketch_8wekyb3d8bbwe!App` 또는 `%SystemRoot%\System32\SnippingTool.exe`). |
| 사용하지 않는 경로 | `Win + Shift + S`가 쓰는 화면 영역 캡처 호출(`ms-screenclip:` URI), 키 입력 주입(SendInput/SendKeys), 캡처용 Win32/WinRT API |
| '새 캡처' 연동 | **선택 기능, 기본값 꺼짐.** 켜면 단축키로 열 때만 캡처 도구 창의 '새 캡처' 버튼을 Windows 접근성 API(UI Automation `InvokePattern`)로 **한 번** 누릅니다. 켤 때마다 "회사 정책상 허용을 확인했는지" 묻습니다. 키 입력 주입이나 마우스 합성은 쓰지 않습니다. |
| 차단 시 | 실행 후 6초 안에 캡처 도구 프로세스가 보이지 않으면 안내 메시지를 **한 번만** 보여 주고 끝냅니다. 이때는 '새 캡처'도 시도하지 않습니다. 다른 경로로 재시도하거나 우회하지 않습니다. |
| Win 키 단축키 | 설정에서 `Win` 조합은 등록할 수 없게 막았습니다(Windows 예약 키와 겹치고, 차단된 단축키를 대신하는 용도로 쓰이지 않게 하기 위함). |
| 권한 | 관리자 권한이 필요 없습니다(`requestedExecutionLevel: asInvoker`). 자동 실행은 HKCU Run 키를 씁니다. |
| 네트워크 | 통신하지 않습니다. |

> 보안 프로그램이 캡처 도구 앱 실행 자체를 막는 환경이라면 이 프로그램으로도 열리지 않으며, 그것이 의도된 동작입니다. 이때는 보안 담당자에게 문의하세요.

## 주요 기능

- **트레이 상주**: 실행하면 시스템 트레이에 아이콘만 보입니다. 설정 창을 닫아도 계속 실행되고, 트레이 메뉴의 **종료**로만 끝납니다.
- **중복 실행 방지**: exe를 다시 실행하면 새로 뜨지 않고 기존 인스턴스의 설정 창이 열립니다(`requestSingleInstanceLock`).
- **전역 단축키**: Electron `globalShortcut`을 사용하므로 다른 프로그램을 쓰는 중에도 동작합니다.
  - 등록은 항상 1개만 유지합니다. 새 키를 등록하기 전에 기존 키를 해제합니다.
  - 새 키 등록에 실패하면(다른 프로그램이 이미 사용 중이면) 기존 키를 다시 등록하고 오류를 보여 줍니다.
  - 연속 입력 방지: 처리 중이거나 직전 처리 후 1초 안에 다시 눌린 입력은 무시합니다.
- **캡처 도구 실행/활성화**
  - 실행 중이 아니면 → 실행 후 프로세스가 떴는지 확인
  - 실행 중이면 → 새 창을 만들지 않고 기존 창을 활성화(신규 앱은 단일 인스턴스로 explorer가 활성화하고, 기존 `SnippingTool.exe`는 `WScript.Shell.AppActivate`로 포커스만 전환)
- **'새 캡처' 자동 실행(선택)**: 아래 ['새 캡처' 자동 실행](#새-캡처-자동-실행) 참고
- **트레이 메뉴**: 캡처 도구 열기 / 단축키 설정 / Windows 시작 시 자동 실행 / 종료
- **다중 모니터**: 설정 창은 마우스 커서가 있는 모니터 가운데에 열립니다. 영역 선택은 캡처 도구 자체 기능이라 모든 모니터를 지원합니다.
- **낮은 리소스 사용**: 폴링이나 타이머 없이 이벤트로만 동작합니다. 하드웨어 가속을 꺼서 GPU 프로세스를 만들지 않습니다.

## 개발 환경

- Windows 10 / 11 (x64)
- Node.js **18 LTS 이상 권장** (Node 16에서도 설치/테스트는 되지만 electron-builder 25는 Node 18 이상에서 검증하는 것이 안전합니다)
- npm

## 설치 및 개발 실행

```bash
npm install
```

```bash
npm start
```

- 실행하면 트레이에 파란 아이콘이 생기고 "트레이에서 실행 중" 알림이 뜹니다.
- `Ctrl + Alt + S`를 누르면 캡처 도구가 열립니다.
- 회사 프록시 때문에 Electron 바이너리 다운로드가 실패하면, 사내에서 쓰는 npm/Electron 미러 설정(`ELECTRON_MIRROR` 등)을 확인하세요.

## 단위 테스트

```bash
npm test
```

Electron 없이 단축키 검증, 설정 정규화, 실행 대상 결정, tasklist 파싱, '새 캡처' 명령 생성을 검증합니다. "어떤 설정에서도 `ms-screenclip` 경로를 쓰지 않는다", "'새 캡처' 스크립트에 키 입력 주입·인코딩 명령·실행 정책 변경이 없다"는 테스트도 들어 있습니다.

## 포터블 exe 빌드

```bash
npm run build
```

- 결과물: **`dist/SnipShortcut-1.0.0-portable.exe`**
- 설치 과정 없이 exe를 원하는 폴더에 두고 실행하면 됩니다.
- 압축을 풀지 않은 폴더 형태가 필요하면 `npm run build:dir` → `dist/win-unpacked/SnipShortcut.exe`
- 처음 빌드할 때 electron-builder가 도구(winCodeSign 등)를 내려받습니다. 사내 네트워크에서 막히면 프록시 설정이나 캐시 폴더(`%LOCALAPPDATA%\electron-builder\Cache`)를 확인하세요.
- exe 아이콘은 기본 Electron 아이콘입니다. 바꾸려면 `build/icon.ico`(256x256 포함)를 넣고 `package.json`의 `build.win.icon`에 `"build/icon.ico"`를 지정하세요.

### 포터블 exe 동작 참고

- 포터블 exe는 실행할 때마다 임시 폴더에 풀려서 실행되므로, 첫 실행은 1~3초 정도 걸릴 수 있습니다.
- 설정은 exe 옆이 아니라 `%APPDATA%\SnipShortcut\settings.json`에 저장됩니다(설정 창 하단 "설정 파일 위치 열기").
- 자동 실행은 원본 exe 경로(`PORTABLE_EXECUTABLE_FILE`)로 등록됩니다. exe를 다른 폴더로 옮겼다면 새 위치에서 한 번 직접 실행하세요. 시작할 때 경로가 다시 등록됩니다.

## 코드 서명 / 실행 허용 정책

- 기본 빌드는 **서명되지 않은 exe**입니다. 다음과 같은 경우가 생길 수 있습니다.
  - SmartScreen "Windows의 PC 보호" 경고 → `추가 정보 → 실행`(회사 정책상 허용될 때만)
  - AppLocker / WDAC / 사내 보안 솔루션이 서명 안 된 exe 실행을 막음
- 회사 배포 정책에 맞추려면 다음 중 하나를 보안 담당자와 협의하세요.
  1. 사내 코드 서명 인증서로 서명: 빌드 시 환경 변수 `CSC_LINK`(pfx 경로), `CSC_KEY_PASSWORD`를 지정하면 electron-builder가 자동 서명합니다. 인증서와 비밀번호는 저장소에 넣지 마세요.
  2. 보안 솔루션에 exe 해시 또는 게시자 기준 실행 허용 등록
- 이 프로그램이 하는 일(캡처 도구 앱 실행, 창 활성화를 위한 `tasklist.exe`/`powershell.exe` 호출, HKCU Run 등록)을 보안 담당자에게 미리 공유하면 허용 검토가 쉽습니다.

## '새 캡처' 자동 실행

설정 창 → **캡처 도구** → "단축키로 열 때 '새 캡처'까지 자동 실행"을 켜면, 단축키 한 번으로 영역 선택 화면까지 이어집니다.

동작 순서
1. 캡처 도구를 실행하거나 기존 창을 활성화합니다(기존 동작과 같음).
2. 창 열기에 성공한 경우에만 `powershell.exe -NoProfile -NonInteractive -Command`로 UI Automation 스크립트를 실행합니다.
3. 캡처 도구 창(`SnippingTool.exe`, `ScreenSketch.exe`, 또는 '캡처 및 스케치' 프레임 창)에서 다음 조건의 버튼을 찾습니다.
   - AutomationId: `NewButton`, `NewSnipButton`, `NewScreenshotButton`
   - 이름: `새 캡처`(현재 Windows 11 캡처 도구), `새로 만들기`(Win10 기존 캡처 도구), `새 스크린샷`, `New`, `New snip`, `New screenshot`, 그리고 `settings.json`의 `newCaptureButtonNames`
   - 비교 전에 `&`, 끝의 단축키 표기(`(Ctrl+N)`, `Ctrl+N`, `(컨트롤+Shift+N)`), 끝의 `(N)` 표기를 지우고 대소문자 구분 없이 비교합니다. 그래서 접근성 이름이 `새 캡처 (Ctrl+N)`이어도 찾습니다.
4. 버튼이 활성화될 때까지 최대 4초 기다린 뒤 `InvokePattern.Invoke()`를 **한 번** 호출합니다.

안전 장치
- 스크립트는 파일로 실행하지 않고 `-Command` 인자로 전달합니다. 그래서 PowerShell 실행 정책을 바꾸지 않습니다(`-ExecutionPolicy` 미사용).
- `-EncodedCommand`, `Invoke-Expression`, `SendKeys`, `SendInput`, 마우스 합성, `ms-screenclip:`이 명령에 들어 있으면 실행 전에 거부합니다(`newCaptureCore.buildCommand`).
- 버튼을 못 찾거나 누르지 못하면 "직접 눌러 주세요" 알림을 한 번 띄우고 끝냅니다. 재시도하지 않습니다.
- 캡처 도구 창 열기가 실패(차단 의심)하면 '새 캡처'는 시도하지 않습니다.
- 보안 프로그램 차단 메시지가 뜨면 이 기능을 끄고 보안 담당자에게 문의하세요.

버튼을 찾지 못할 때
1. 캡처 도구 창은 찾았지만 버튼을 못 찾으면, 그 창에서 발견한 버튼 목록(최대 15개, `이름 [AutomationId]`)이 메시지 박스로 표시됩니다.
2. 목록에서 새 캡처 버튼에 해당하는 이름을 찾아 설정 파일(설정 창 하단 "설정 파일 위치 열기" → `settings.json`)에 추가합니다. 다시 빌드할 필요가 없습니다.

   ```json
   {
     "newCaptureButtonNames": ["새 캡처 시작"]
   }
   ```

   - 문자열만, 1~40자, 큰따옴표·제어문자 불가, 최대 10개. 조건에 맞지 않는 값은 무시됩니다.
   - 금지 호출 이름(`SendKeys` 등)이 들어가면 명령 생성 단계에서 거부되고 오류가 표시됩니다.
3. 프로그램을 종료 후 다시 실행하면 적용됩니다(설정 파일은 시작할 때 읽습니다).
4. 기본 후보 자체를 바꾸려면 `src/main/newCaptureCore.js`의 `TARGET`을 수정합니다. 정규화 규칙을 바꿀 때는 `invoke-new.ps1`의 `Get-NormalizedName`과 `newCaptureCore.normalizeButtonName`을 같이 고쳐야 합니다(테스트가 두 패턴이 같은지 확인).

## 오류 처리

| 상황 | 동작 |

## 알려진 제한

- '새 캡처' 자동 실행은 캡처 도구의 접근성 정보(버튼 이름/AutomationId)에 의존합니다. 캡처 도구가 업데이트되면 동작하지 않을 수 있으며, 그때는 창만 열리는 동작으로 돌아갑니다.
- Windows 11 캡처 도구가 마지막에 **녹화 모드**로 설정되어 있으면 '새 캡처'가 화면 녹화 영역 선택으로 시작될 수 있습니다. 캡처 도구에서 스크린샷 모드로 바꿔 두세요.
- '새 캡처'는 PowerShell 기동과 UI Automation 로딩 때문에 단축키를 누른 뒤 영역 선택 화면이 뜨기까지 1~2초 정도 걸릴 수 있습니다.
- 보안 프로그램이 영역 선택 화면 자체를 막으면 자동 실행으로도 열리지 않습니다. 의도된 동작입니다.
- Windows 알림(토스트)은 집중 지원(방해 금지) 상태에서는 보이지 않을 수 있습니다. 차단 의심 경고는 메시지 박스로 표시되므로 알림 설정과 상관없이 보입니다.
- 관리자 권한으로 실행 중인 창이 포커스를 갖고 있으면, 일반 권한 프로그램의 전역 단축키가 Windows 정책(UIPI)에 따라 동작하지 않을 수 있습니다.
